## 项目目的

### 用户提出的目标

用户使用 Thermalright TRCCCAP 软件控制 PS120 DIGITAL 数码显示屏，希望：

> 显示屏只显示 CPU 温度，GPU 温度、功耗、频率、占用率、风扇、硬盘、网络等其他内容都不显示。

原程序安装在：

\`C:\Program Files\TRCCCAP\`

用户还明确要求：

- 不修改原安装目录中的程序；
- 所有复制品、代码和测试文件放在 \`D:\TRCC\`；
- 后续整理出一个可以上传 GitHub 的目录；
- 在没有确认成功之前，不把实验程序当成可用程序。

### ChatGPT 执行的工作

ChatGPT 在 \`D:\TRCC\github_upload\` 中保存了原程序的复制品、依赖文件、反编译结果和实验性修改版本。原安装目录没有被修改。

## 用户提出的方案

用户提出的总体思路是：

1. 先复制原程序，不直接修改原安装目录；
2. 研究 TRCCCAP 是否是 .NET Framework WinForms 程序；
3. 通过反编译或修改 .NET 程序中的界面和显示逻辑；
4. 尝试将显示内容改成只保留 CPU 温度；
5. 如果软件层面无法可靠修改，再研究 USB/HID 通信协议；
6. 更进一步，可以自己编写程序控制显示屏，或者研究是否能使用其他兼容显示设备。

用户还提出了一个关键疑问：既然显示屏通过主板上的 JUSB1/JUSB2 接口连接，程序是否可以直接获得 GPU 温度并自行决定显示内容。

ChatGPT 的分析是：获取 GPU 温度和控制显示屏是两个不同问题。能读到 GPU 温度，并不代表已经知道显示屏需要什么 USB/HID 报文格式；真正自己控制显示屏，还需要确认设备身份和通信协议。

## VID/PID：来源、责任归属和不确定性

### ChatGPT 做了什么

在显示屏保持插入、无法拔插对照的情况下，ChatGPT 使用 Windows 设备枚举查看了连接中的 HID 设备，发现一个候选设备：

- USB 设备标识：\`USB\\VID_0416&PID_8001\`
- 设备描述：\`USB Input Device\`
- HID 描述：\`HID-compliant vendor-defined device\`
- 总线描述：\`HID Transfer\`

### 这不是用户确认的结果

\`0416:8001\` 不是用户从 PS120 外壳、说明书或厂商资料中提供的 VID/PID，也没有经过拔出显示屏再插回去的对照确认。

因此，\`0416:8001\` 只能写成：

> ChatGPT 通过 Windows 设备枚举找到的、可能与显示屏有关的候选 VID/PID。

不能写成：

> 已确认的 PS120 官方 VID/PID。

### ChatGPT 的判断边界

目前不能排除以下情况：

- \`0416:8001\` 是电脑中的其他 HID 设备；
- 这个设备确实是显示屏，但还需要接口、端点或报告描述符才能正确通信；
- 多个设备共用同一个 VID/PID；
- VID/PID 正确，但实际显示协议、数据格式或初始化流程仍然未知。

原 TRCCCAP 软件不要求用户手动输入 VID/PID，并不表示它完全不使用设备识别信息。它可能在程序内部自动枚举 HID 设备，再根据接口、报告描述符、序列号或其他条件选择目标设备。这个内部过程目前没有被完整确认。

## 当前结论

### 用户的目标是否完成

没有完成。

目前没有一个已经被硬件验证成功的“只显示 CPU 温度”版本。用户已经反馈之前的修改版本仍然显示其他内容，这个反馈应当作为项目当前状态的一部分保留。

### ChatGPT 已完成的工作

- 复制原程序并保留原始备份；
- 将实验文件集中到 \`D:\TRCC\github_upload\`；
- 对 .NET 程序进行静态分析；
- 尝试修改显示项目选择和数码显示调用；
- 枚举到一个可能相关但未确认的 HID 设备；
- 整理反编译结果和失败实验记录；
- 编写本 README，区分用户要求与 ChatGPT 执行内容。

### 尚未完成的工作

- 确认 PS120 显示屏对应的准确 USB 设备；
- 获取并理解 TRCCCAP 与显示屏之间的真实 HID/USB 报文；
- 根据真实协议重新编写可靠的显示程序；
- 在硬件上验证只显示 CPU 温度的效果。

因此，当前仓库应被视为**用户需求和 ChatGPT 失败实验的记录**，不能把其中的 \`TRCC_CPU_ONLY.exe\` 当作已经成功的软件使用。
